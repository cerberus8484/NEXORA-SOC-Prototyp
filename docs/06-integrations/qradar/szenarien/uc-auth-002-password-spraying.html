UC-AUTH-002 — Password Spraying

Umgekehrtes Brute-Force: wenige (oft nur 1–2) gängige Passwörter gegen viele Konten. So bleibt jeder einzelne Account unter der Lockout-Schwelle, während der Angreifer trotzdem breit testet. Erkennbar an vielen fehlgeschlagenen Logins gegen unterschiedliche Benutzer von einer Quelle.

MITRE: T1110.003 Taktik: Credential Access Confidence: 70–88 Status: DRAFT → zu validieren Quelle: Windows Security 4625

1 · Szenario

Der Angreifer kennt (oder rät) die Namenskonvention der Domäne und hat eine User-Liste (LinkedIn, OSINT, frühere Enumeration). Er testet ein gängiges Passwort (Winter2026!, Firmenname123) gegen alle Konten. Pro Konto nur 1 Versuch → kein Account-Lockout, klassisches Brute-Force-Alerting greift nicht.

Kernunterschied zu UC-AUTH-001: Brute Force = viele Versuche, ein User. Spraying = wenige Versuche, viele User. Darum zählt diese Regel unterschiedliche Usernames pro Quelle.

2 · Angriffsablauf

  1. User-Enumeration: Sammeln gültiger Benutzernamen (OSINT, Kerberos-Enum, O365).
  2. Spray-Runde: Ein Passwort gegen alle Konten — viele 4625-Events mit gleicher Source IP, unterschiedlichen Target-Usern.
  3. Pause & Wiederholung: Nach Stunden/Tagen nächstes Passwort (Lockout-Reset abwarten).
  4. Treffer: Ein 4624 (Success) für eines der Konten → Valid Accounts (T1078).

4 · Voraussetzungen

  • Windows Security Event Log liefert EventID 4625 (Login Failure) inkl. Target-Username + Source.
  • Reference Set: RS:ServiceAccounts (AlphaNumeric) — Dienstkonten, die durch alte Cached-Credentials Failures erzeugen.

5 · Erkennungslogik

Actions → New Event Rule · Rule Group Authentication · Name UC-AUTH-002 Password Spraying.

Apply UC-AUTH-002 Password Spraying on events detected by the Local system
and when the event QID is one of the following (Windows Login Failure / 4625)
and when at least 10 events are seen with the same Source IP
        and different Username in 15 minutes
and when the username is NOT contained in RS:ServiceAccounts
Test-Name: when at least N events are seen with the same <Source IP> and different <Username> in <time> — „different Username" ist der Kern. Optional Failure-Code 0x18 (falsches Passwort, Konto existiert) ergänzen, um Tippfehler/nicht existente User zu trennen.

10 · Analyst-Handlung

  • Liste der getesteten Usernames + Source IP sichern.
  • Gab es einen 4624-Success für eines der Konten? → Konto sperren/zurücksetzen.
  • MFA-Status der Domäne prüfen; Spraying ist gegen MFA meist wirkungslos.
  • Quelle blockieren (FW/Conditional Access), Geo/Reputation anreichern.
