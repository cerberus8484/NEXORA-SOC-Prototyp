UC-CRED-001 — LSASS Memory Access

Der LSASS-Prozess (lsass.exe) hält Klartext-Passwörter, NTLM-Hashes und Kerberos-Tickets angemeldeter Nutzer im Speicher. Wer ihn ausliest oder dumpt, erntet Credentials für Lateral Movement und Privilege Escalation. Klassische Tools: Mimikatz, ProcDump, comsvcs.dll MiniDump, Nanodump.

MITRE: T1003.001 Taktik: Credential Access Confidence: 95–98 Status: DRAFT → zu validieren Quelle: Sysmon Event 10 Windows 4656

1 · Szenario

Nach erstem Zugriff mit lokalen Admin-Rechten greift der Angreifer auf den Speicher von lsass.exe zu. Entweder direkt (Mimikatz sekurlsa::logonpasswords) oder per Dump-zu-Datei (ProcDump, Task Manager, comsvcs.dll), den er offline auswertet. Das verschafft ihm Credentials weiterer — oft höher privilegierter — Konten, die auf dem Host angemeldet waren.

Hoch-kritisch: Ein erfolgreicher LSASS-Dump auf einem Server, an dem ein Domänen-Admin angemeldet war, kann die gesamte Domäne kompromittieren.

2 · Angriffsablauf

  1. Lokaler Admin / SYSTEM: Angreifer hat erhöhte Rechte auf dem Host.
  2. Zugriff auf LSASS: Öffnen des lsass.exe-Handles mit Lese-/Dump-Rechten (PROCESS_VM_READ). Sysmon Event 10 protokolliert den Zugriff samt GrantedAccess.
  3. Extraktion: Direktauslesen (Mimikatz) oder Dump-Datei (.dmp in %TEMP%). Sysmon Event 11 protokolliert die Dump-Datei.
  4. Verwertung: Klartext-Passwörter / NTLM-Hashes / Tickets → Pass-the-Hash, Pass-the-Ticket, Lateral Movement.

5 · Voraussetzungen

  • Sysmon mit ProcessAccess-Logging (Event 10), Filter auf TargetImage=lsass.exe. Alternativ Windows-Audit „Handle Manipulation" (4656) — gröber.
  • Custom Properties: TargetImage GrantedAccess SourceImage CallTrace
  • Reference Set: RS:EDR-Diagnostic-Hosts (IP).
  • Building Block: BB:KnownLSASSReaders — legitime Zugreifer (MsMpEng, werfault, EDR-Binaries).

6 · Erkennungslogik

Actions → New Event Rule · Rule Group Credential Access · Name UC-CRED-001 LSASS Access.

Apply UC-CRED-001 LSASS Access on events detected by the Local system
and when the event QID is one of the following (Sysmon Event 10 — ProcessAccess)
and when TargetImage (custom) matches the regex (?i)\\lsass\.exe$
and when GrantedAccess (custom) is one of the following 0x1010,0x1410,0x1438,0x143a,0x1fffff
and when the source IP is NOT contained in RS:EDR-Diagnostic-Hosts
and when SourceImage (custom) is NOT contained in BB:KnownLSASSReaders
EDR-Whitelist ist Pflicht. AV/EDR greift permanent auf LSASS zu. Ohne BB:KnownLSASSReaders feuert die Regel bei jedem Defender-Scan — unbrauchbar.

11 · Analyst-Handlung & Evidence

  • Quell-Prozess (SourceImage), PID, Parent, Commandline → welches Tool?
  • CallTrace prüfen (UNKNOWN/unbeschriebener Speicher = injizierter Code).
  • Folge-Events: .dmp-Datei (Sysmon 11)? Ausgehende Verbindung?
  • Welche Konten waren auf dem Host angemeldet (4624) → potenziell kompromittiert.

Sofortmaßnahmen: Host isolieren, betroffene Konten-Passwörter rotieren (inkl. ggf. Domänen-Admin / krbtgt zweimal), Persistenz suchen.
