UC-LAT-002 — RDP from Unusual Source / Pivoting

RDP (Remote Desktop, Logon Type 10) ist ein Standard-Admin-Werkzeug — und ein Standard-Angriffsweg. Verdächtig wird es, wenn die Quelle ungewöhnlich ist (keine Helpdesk-/Jump-/Citrix-Infra) oder wenn ein Host als RDP-Ziel und -Quelle auftritt: das ist Pivoting durch das Netz.

MITRE: T1021.001 Taktik: Lateral Movement Confidence: 75–92 Status: DRAFT → zu validieren Quelle: Windows Security 4624 (Type 10)

1 · Szenario

Der Angreifer nutzt erbeutete Credentials, um sich per RDP von Host zu Host zu hangeln. Jeder kompromittierte Rechner wird zum Sprungbrett (Pivot) zum nächsten. Da RDP ein legitimes Protokoll ist, liegt das Signal nicht im „ob", sondern im Muster: untypische Quelle und/oder ein Host, der kurz hintereinander RDP-Ziel und RDP-Quelle ist.

2 · Angriffsablauf

  1. Credentials: Angreifer hat gültige (oft Admin-)Zugangsdaten.
  2. Erster RDP-Hop: Logon Type 10 auf Host A — von einer Quelle außerhalb der Admin-/Helpdesk-Infra.
  3. Pivot: Von Host A aus RDP auf Host B, von B auf C … Host A erscheint als Ziel und Quelle.
  4. Ziel erreicht: Zugriff auf File-Server, DC, Datenbank.

4 · Voraussetzungen

  • Windows liefert 4624 mit Logon Type und Source Network Address.
  • Custom Property: Logon Type
  • Reference Sets: RS:Helpdesk-Workstations RS:Jump-Hosts RS:Citrix-Servers

5 · Erkennungslogik

Actions → New Event Rule · Rule Group Lateral Movement · Name UC-LAT-002 RDP Unusual Source.

-- Basis: RDP aus untypischer Quelle
Apply UC-LAT-002 RDP Unusual Source on events detected by the Local system
and when the event QID is one of the following (Successful Logon / 4624)
and when Logon Type (custom) is one of the following 10
and when the source IP is NOT contained in RS:Helpdesk-Workstations
and when the source IP is NOT contained in RS:Jump-Hosts
and when the source IP is NOT contained in RS:Citrix-Servers
Pivoting-Verschärfung (Conf ~90): zusätzlicher Test —
and when at least 3 events are seen with the same Source IP and different Destination IP in 30 minutes
Ein Host, der auf mehrere Ziele RDP-t = PIVOTING.

10 · Analyst-Handlung

  • Quelle + Konto + Zielkette rekonstruieren (alle 4624 Type 10 derselben Quelle/Kette).
  • Ist die Quelle bekannt/legitim? Konto zu dieser Uhrzeit plausibel?
  • Bei Pivoting: alle Hops als potenziell kompromittiert behandeln.
  • Konto sperren/zurücksetzen, betroffene Hosts isolieren, RDP-Exposure (NLA, MFA, FW) prüfen.
