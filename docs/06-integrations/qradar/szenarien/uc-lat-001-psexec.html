UC-LAT-001 — PsExec Lateral Movement

PsExec (und Klone wie PAExec, RemCom) führen Befehle remote aus, indem sie über die ADMIN$-Freigabe ein Service-Binary ablegen und einen Dienst (PSEXESVC) installieren. Das erzeugt ein charakteristisches Paar: Service-Install (7045) + Remote-Logon (4624 Type 3) von derselben Quelle.

MITRE: T1021.002 Taktik: Lateral Movement Confidence: 85–97 Status: DRAFT → zu validieren Quelle: System 7045 Security 4624

1 · Szenario

Nach Erlangen von Admin-Credentials bewegt sich der Angreifer seitlich: PsExec kopiert ein Binary auf das Ziel (\\TARGET\ADMIN$), registriert es als Dienst und startet es als SYSTEM. So führt er Befehle auf entfernten Hosts aus — ohne RDP, ohne interaktive Session.

2 · Angriffsablauf

  1. Admin-Credentials: Angreifer besitzt lokale/Domänen-Admin-Rechte (z. B. nach LSASS-Dump).
  2. Binary-Drop: Service-Executable wird auf ADMIN$ des Ziels geschrieben (Sysmon 11).
  3. Service-Install: Dienst PSEXESVC (o. ä.) wird registriert → EventID 7045.
  4. Remote-Logon: Authentifizierung am Ziel → 4624 Logon Type 3 von der Quell-IP.
  5. Ausführung: Befehle laufen als SYSTEM; bei mehreren Zielen entsteht eine Hop-Kette.

4 · Voraussetzungen

  • Windows liefert 7045 (Service Installed) und 4624 (Logon) mit Logon Type.
  • Custom Property: Service Name Logon Type
  • Reference Sets: RS:SCCM-Servers RS:Jump-Hosts RS:ServiceAccounts

5 · Erkennungslogik (zweistufig)

Stärkstes Signal = beide Ereignisse korreliert. In QRadar sauber als zwei Building Blocks + eine Korrelations-Regel (nur diese erzeugt die Offense).

-- Building Block A: PsExec-Dienst-Installation (KEINE Offense)
Apply BB:PsExecServiceInstall on events detected by the Local system
and when the event QID is one of the following (Service Installed / 7045)
and when Service Name (custom) matches the regex (?i)(psexesvc|paexec|remcom|execsvc)

-- Building Block B: Remote-Logon Type 3 (KEINE Offense)
Apply BB:RemoteType3Logon on events detected by the Local system
and when the event QID is one of the following (Successful Logon / 4624)
and when Logon Type (custom) is one of the following 3
and when the username is NOT contained in RS:ServiceAccounts
and when the source IP is NOT contained in RS:SCCM-Servers
and when the source IP is NOT contained in RS:Jump-Hosts

-- Korrelations-Regel (erzeugt die Offense)
Apply UC-LAT-001 PsExec
and when BB:PsExecServiceInstall matches
        and BB:RemoteType3Logon matches
        with the same Source IP within 2 minutes
Building Blocks bekommen keine „Ensure offense"-Response. Nur die finale Korrelations-Regel erzeugt die Offense — sonst zwei Fehlalarme statt eines echten.

10 · Analyst-Handlung

  • Quelle (Source IP) + verwendetes Admin-Konto → Ausgangspunkt der Bewegung.
  • Ziel-Hosts (alle 4624 Type 3 derselben Quelle) → Umfang der Ausbreitung.
  • Auf Zielen: welche Befehle lief der Dienst? Folge-Persistenz?
  • Admin-Konto sperren/zurücksetzen, betroffene Hosts isolieren.
