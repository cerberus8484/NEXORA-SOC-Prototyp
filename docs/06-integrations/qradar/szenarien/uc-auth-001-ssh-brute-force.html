UC-AUTH-001 — SSH Brute Force

Ein Angreifer probiert von einer Quelle viele Passwörter gegen einen oder wenige SSH-Accounts durch. Typisch gegen exponierte Linux-Hosts, Honeypots (Cowrie) und Firewall-Management-Interfaces. Erkennbar an der Häufung fehlgeschlagener Logins von derselben Quell-IP.

MITRE: T1110.001 Taktik: Credential Access Confidence: 75–90 Status: DRAFT → zu validieren Quelle: Cowrie / sshd / OPNsense

1 · Szenario

Automatisierte Tools (Hydra, Medusa, ncrack, Botnetze) fahren Wörterbuch- oder Credential-Stuffing-Angriffe gegen SSH (Port 22). Auf exponierten Systemen ist das Dauer-Grundrauschen; relevant wird es bei fokussierten Angriffen auf interne Hosts oder bei plötzlichem Volumen-Anstieg.

2 · Angriffsablauf

  1. Zielwahl: Angreifer findet einen erreichbaren SSH-Dienst (Scan, Shodan).
  2. Credential-Durchlauf: Schnelle Folge von Login-Versuchen mit Passwort-Listen → viele User Login Failure-Events von einer Quell-IP.
  3. Treffer: Bei Erfolg ein Login Success nach vielen Failures → Folge-Use-Case „Failure followed by Success".
  4. Verwertung: Shell-Zugriff → Persistenz, Lateral Movement, Krypto-Miner.

4 · Voraussetzungen

  • Log-Quelle liefert SSH-Login-Failures, gemappt auf QID-Kategorie Authentication > User Login Failure.
  • Reference Set: RS:TrustedAuthSources (Type IP) — Scanner-, Monitoring- und Admin-IPs.

5 · Erkennungslogik

Actions → New Event Rule · Rule Group Authentication · Name UC-AUTH-001 SSH Brute Force.

Apply UC-AUTH-001 SSH Brute Force on events detected by the Local system
and when the event category for the event is one of the following Authentication > User Login Failure
and when the destination port is one of the following 22
and when at least 8 events are seen with the same Source IP in 5 minutes
and when the source IP is NOT contained in RS:TrustedAuthSources
Verschärfung „Failure → Success": Zweite Regel, die nach dieser Offense ein erfolgreiches Login Success von derselben Source IP/auf demselben Ziel erkennt → Confidence stark hoch (möglicher Kompromiss).

10 · Analyst-Handlung

  • Source IP → Geo/Reputation (Threat-Intel-Anreicherung).
  • Gab es einen Login Success? Wenn ja → Konto als kompromittiert behandeln.
  • Zielsystem: extern erreichbar? SSH härten (Key-only, fail2ban, Portänderung, Allowlist).
