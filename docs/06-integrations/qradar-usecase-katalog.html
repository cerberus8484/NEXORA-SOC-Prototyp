QRadar Use-Case-Katalog

Sechs fertig formulierte Use Cases zum direkten Nachbauen im Rule Wizard. Jeder Use Case ist in der GUI-Test-Sprache geschrieben, die in der Klick-Anleitung Schritt 3–4 beschrieben ist. Blau unterstrichene Werte sind die anklickbaren Parameter im Wizard.

Confidence-Scores und FP-Quellen stammen aus dem SOC-Hunt-Framework (Tier 1–3). Status pro Use Case: DRAFT → in Testumgebung validieren → ACTIVE (erst wenn FP-Rate < 5 %).

Voraussetzung lesen. Mehrere Use Cases brauchen Custom Event Properties (CommandLine, GrantedAccess, Service Name, Logon Type, Ticket Encryption Type) und Reference Sets. Fehlen diese Felder, feuert die Regel nicht. Beides vor dem Bau anlegen.
90–100 sofort eskalieren 70–89 an Analyst 50–69 Ticket + Analyse

Pro Use Case findest du: Voraussetzungen · Rule Wizard-Auswahl (Regeltyp + Group) · Tests (1:1 in den Wizard übernehmen) · Rule Response (Offense-Index, Limiter, Severity) · FP-Whitelist · MITRE-Mapping für die Use Case Manager App.

UC-AUTH-001

SSH Brute Force

Conf 75–90
Taktik: Credential Access MITRE: T1110.001 Quellen: Linux/SSH-Auth (Cowrie, sshd, OPNsense)

1 Voraussetzungen

  • Log-Quelle liefert SSH-Login-Failures (QID-Kategorie Authentication > User Login Failure).
  • Reference Set RS:TrustedAuthSources (Type IP) — Admin-/Scanner-IPs.

2 Rule Wizard

Actions → New Event RuleRule Group: AuthenticationName: UC-AUTH-001 SSH Brute Force

3 Tests (in den Regel-Bereich übernehmen)

Apply UC-AUTH-001 SSH Brute Force on events which are detected by the Local system
and when the event category for the event is one of the following Authentication > User Login Failure
and when the destination port is one of the following 22
and when at least 8 events are seen with the same Source IP in 5 minutes
and when the source IP is NOT contained in RS:TrustedAuthSources

4 Rule Response

EinstellungWert
Ensure event is part of an offense✓ — Index by: Source IP
Severity / MagnitudeSeverity 6
Response Limiter1× pro 10 min pro Source IP
Enable Rule✓

Fehlkonfigurierter Client (User tippt falsch)Schwelle 8/5min; ggf. „same Username" ergänzen

UC-AUTH-002

Password Spraying (Windows)

Conf 70–88
Taktik: Credential Access MITRE: T1110.003 Quellen: Windows Security (4625)

1 Voraussetzungen

  • Windows Security Event Log liefert EventID 4625 (Login Failure).
  • Reference Set RS:ServiceAccounts (AlphaNumeric) — bekannte Dienstkonten.
Unterschied zu Brute Force: Spraying = viele verschiedene Benutzer, wenige Versuche je User, von einer Quelle. Darum „same Source IP" + Zählung über unterschiedliche Usernames.

2 Rule Wizard

Actions → New Event RuleRule Group: AuthenticationName: UC-AUTH-002 Password Spraying

3 Tests

Apply UC-AUTH-002 Password Spraying on events detected by the Local system
and when the event QID is one of the following (Windows Login Failure / 4625)
and when at least 10 events are seen with the same Source IP
        and different Username in 15 minutes
and when the username is NOT contained in RS:ServiceAccounts
Test-Name im Stack: when at least N events are seen with the same X and different Y

4 Rule Response

EinstellungWert
Offense✓ — Index by: Source IP
Severity7
Response Limiter1× pro 30 min pro Source IP

5 False Positives / Whitelist

QuelleMaßnahme
Abgelaufenes Passwort auf Multi-User-TerminalSchwelle & Zeitfenster; Terminal-IP prüfen
Dienstkonto mit altem Cached-CredentialRS:ServiceAccounts

UC-CRED-001

LSASS Memory Access (Credential Dump)

Conf 95–98
Taktik: Credential Access MITRE: T1003.001 Quellen: Sysmon EventID 10 (bevorzugt) / Windows 4656

1 Voraussetzungen

  • Sysmon mit ProcessAccess-Logging (Event 10) ODER Windows Audit „Handle Manipulation" (4656).
  • Custom Properties: TargetImage, GrantedAccess, SourceImage (Sysmon) bzw. ObjectName, AccessMask, ProcessName (4656). Siehe Custom Properties.
  • Reference Set RS:EDR-Diagnostic-Hosts (IP) für AV/EDR/Debugging-Ausnahmen.

2 Rule Wizard

Actions → New Event RuleRule Group: Credential AccessName: UC-CRED-001 LSASS Access

3 Tests (Sysmon-Variante)

Apply UC-CRED-001 LSASS Access on events detected by the Local system
and when the event QID is one of the following (Sysmon Event 10 — ProcessAccess)
and when TargetImage (custom) matches the following regex (?i)\\lsass\.exe$
and when GrantedAccess (custom) is one of the following 0x1010,0x1410,0x1438,0x143a,0x1fffff
and when the source IP is NOT contained in RS:EDR-Diagnostic-Hosts
and when SourceImage (custom) is NOT contained in BB:KnownLSASSReaders (MsMpEng/werfault/EDR)

4 Rule Response

EinstellungWert
Offense✓ — Index by: Source IP (Host)
Severity / MagnitudeSeverity 9 (kritisch)
Dispatch / NotifyEmail an SOC + Custom Action „enrich host"
Response Limiter1× pro 15 min pro Host

5 False Positives / Whitelist

QuelleErkennungMaßnahme
AV/EDR (MsMpEng, CrowdStrike, SentinelOne)SourceImage = EDR-BinaryBB:KnownLSASSReaders
WER (werfault.exe) nach AbsturzSourceImage = werfault.exeBuilding Block
Debugger auf Dev-MaschinenVS / WinDbgRS:EDR-Diagnostic-Hosts
Nie blind isolieren. Confidence ist hoch, aber EDR-Whitelist muss sitzen — sonst feuert die Regel bei jedem Defender-Scan.

UC-CRED-002

Kerberoasting

Conf 85–90
Taktik: Credential Access MITRE: T1558.003 Quellen: Windows Security 4769 (DC)

1 Voraussetzungen

  • Domain Controller liefert EventID 4769 (Kerberos Service Ticket).
  • Custom Properties: Ticket Encryption Type, Service Name, Account Name.
  • Reference Set RS:Kerberos-Service-Hosts (IP) — SQL/Exchange/legitime Ticket-Anforderer.
Kern-Indikator: Ticket Encryption Type = 0x17 (RC4-HMAC). Kerberoasting funktioniert nur mit RC4, nicht mit AES (0x12). Viele verschiedene SPNs in kurzer Zeit von einer Workstation.

2 Rule Wizard

Actions → New Event RuleRule Group: Credential AccessName: UC-CRED-002 Kerberoasting

3 Tests

Apply UC-CRED-002 Kerberoasting on events detected by the Local system
and when the event QID is one of the following (Kerberos Service Ticket / 4769)
and when Ticket Encryption Type (custom) is one of the following 0x17
and when Service Name (custom) does NOT match regex (krbtgt|\$$)
and when at least 10 events are seen with the same Source IP
        and different Service Name in 1 hour
and when the source IP is NOT contained in RS:Kerberos-Service-Hosts

4 Rule Response

EinstellungWert
Offense✓ — Index by: Source IP
Severity8
Response Limiter1× pro 1 h pro Source IP

5 False Positives / Whitelist

QuelleMaßnahme
SQL Server / Exchange fordert regelmäßig TicketsHost in RS:Kerberos-Service-Hosts
Monitoring-Skripte gegen DiensteQuelle ist definierter Service-Host, keine Workstation

UC-LAT-001

PsExec Lateral Movement

Conf 85–97
Taktik: Lateral Movement MITRE: T1021.002 Quellen: System 7045 + Security 4624 (Type 3)

1 Voraussetzungen

  • Windows liefert EventID 7045 (Service Install) und 4624 (Logon) mit Logon Type.
  • Custom Property: Service Name.
  • Reference Sets: RS:SCCM-Servers, RS:Jump-Hosts, RS:ServiceAccounts.
Zweistufige Logik. Stärkstes Signal: Service-Install und Type-3-Logon von derselben Quelle kurz hintereinander. In QRadar sauber über einen Building Block je Teil + eine korrelierende Regel, oder eine Regel mit „when these rules match in sequence".

2 Rule Wizard

Actions → New Event RuleRule Group: Lateral MovementName: UC-LAT-001 PsExec

3 Tests

-- Building Block A: PsExec-Dienst
Apply BB:PsExecServiceInstall on events detected by the Local system
and when the event QID is one of the following (Service Installed / 7045)
and when Service Name (custom) matches regex (?i)(psexesvc|paexec|remcom|execsvc)

-- Building Block B: Remote-Logon
Apply BB:RemoteType3Logon on events detected by the Local system
and when the event QID is one of the following (Successful Logon / 4624)
and when Logon Type (custom) is one of the following 3
and when the username is NOT contained in RS:ServiceAccounts
and when the source IP is NOT contained in RS:SCCM-Servers
and when the source IP is NOT contained in RS:Jump-Hosts

-- Korrelations-Regel (erzeugt Offense)
Apply UC-LAT-001 PsExec
and when BB:PsExecServiceInstall matches
        and BB:RemoteType3Logon matches
        with the same Source IP within 2 minutes
Korrelations-Test im Stack: when these rules, in any order, match … bzw. when an event matches all of the following BBs.

4 Rule Response

EinstellungWert
Offense (nur auf der Korrelations-Regel!)✓ — Index by: Source IP
Severity9
Response Limiter1× pro 10 min pro Source IP
Building Blocks erzeugen keine Offense. Bei BB:* im Wizard keine „Ensure offense"-Response setzen — nur die finale Regel.

UC-LAT-002

RDP from Unusual Source / Pivoting

Conf 75–92
Taktik: Lateral Movement MITRE: T1021.001 Quellen: Windows Security 4624 (Type 10)

1 Voraussetzungen

  • Windows liefert 4624 mit Logon Type.
  • Reference Sets: RS:Helpdesk-Workstations, RS:Jump-Hosts, RS:Citrix-Servers.

2 Rule Wizard

Actions → New Event RuleRule Group: Lateral MovementName: UC-LAT-002 RDP Unusual Source

3 Tests

Apply UC-LAT-002 RDP Unusual Source on events detected by the Local system
and when the event QID is one of the following (Successful Logon / 4624)
and when Logon Type (custom) is one of the following 10
and when the source IP is NOT contained in RS:Helpdesk-Workstations
and when the source IP is NOT contained in RS:Jump-Hosts
and when the source IP is NOT contained in RS:Citrix-Servers
Pivoting-Verschärfung (höhere Confidence): zusätzlich „at least 3 events with the same Source IP and different Destination IP in 30 minutes" → ein Host springt auf viele Ziele = PIVOTING (Conf ~90).

4 Rule Response

EinstellungWert
Offense✓ — Index by: Source IP
Severity7 (Single) / 9 (Pivoting)
Response Limiter1× pro 30 min pro Source IP

5 False Positives / Whitelist

QuelleMaßnahme

Admin über Jump-/Citrix-ServerRS:Jump-Hosts / RS:Citrix-Servers
