Use Case in QRadar über die GUI anlegen

Schritt-für-Schritt-Klickanleitung. Ein „Use Case" in QRadar = eine Custom Rule in der Correlation Rule Engine (CRE), optional mit Building Blocks, Reference Sets und MITRE-Mapping in der Use Case Manager-App. Die GUI-Bilder sind maßstabsgetreue Nachbauten (keine Original-Screenshots) — die Position der Klick-Ziele entspricht QRadar 7.4 / 7.5.

0Voraussetzungen

  1. Benutzerrolle mit Recht Maintain Custom Rules — prüfbar unter Admin → User Roles → Offenses.
  2. Log-Quellen liefern bereits Events (Kontrolle im Tab Log Activity).
  3. Für Listen/Whitelists: ggf. Reference Set vorab anlegen (siehe Schritt 5).

1Rule Wizard öffnen

Einstieg über den Tab Offenses. Alle drei Wege (Offenses / Log Activity / Network Activity) öffnen denselben Wizard.

  1. Oben den Tab Offenses öffnen.
  2. Im linken Menü Rules anklicken.
  3. Oben rechts den Button Actions ▾ öffnen.
  4. Im Dropdown New Event Rule wählen → der Rule Wizard startet.

2Regeltyp verstehen

Die Auswahl im Actions-Menü bestimmt, worauf die Regel reagiert:

AuswahlReagiert aufWann nutzen
New Event Ruleeinzelne Log-Eventshäufigster Fall (Logins, Firewall, Auth …)
New Flow RuleNetzwerk-FlowsQFlow / NetFlow, Datenvolumen, Beaconing
New Common RuleEvents und FlowsTests, die für beide Quellen gelten
New Offense Rulebestehende OffensesEskalation / Anreicherung vorhandener Offenses
Building Block statt Regel? Soll der Use Case nur als wiederverwendbare Teilbedingung dienen (keine Offense), im Wizard später Building Block statt einer Response wählen — identische Test-Seite, aber ohne Offense-Erzeugung.

3Tests zusammenbauen (Rule Wizard)

Im Wizard so lange Next klicken, bis die Test-Seite erscheint. Links steht der Test-Stack — Tests per Klick nach oben übernehmen und über die blau unterstrichenen Parameter konkretisieren.

  1. Im Feld oben einen Regelnamen tippen, z. B. UC-AUTH-001 SSH Brute Force.
  2. Links einen Test anklicken (z. B. when at least N events are seen with same property) — er erscheint oben im Regel-Bereich.
  3. Oben jeden blau unterstrichenen Parameter anklicken und konkretisieren (QID, 5, Source IP, 5 minutes, Whitelist-BB).
  4. Weitere Tests ergänzen, dann Next.

Beispiel-Logik im Klartext

Apply UC-AUTH-001 SSH Brute Force on events detected by the Local system
and when the event QID is one of the following (SSH Login Failed)
and when at least 5 events are seen with the same Source IP in 5 minutes
and when the source IP is not contained in BB:HostDefinition: Trusted Auth Sources
Schwellwert-Test ist der Kern jeder Korrelation. „same Source IP" / „same Username" sauber wählen — sonst zu viele (jede IP einzeln) oder zu wenige Treffer.

4Response & Offense konfigurieren

Letzte Wizard-Seite: festlegen, was passiert, wenn die Regel feuert — und wodurch die Offense indexiert wird.

  1. Rule Group zuweisen (z. B. Authentication) — wichtig fürs Wiederfinden.
  2. Ensure the detected event is part of an offense anhaken.
  3. Index offense based on auf Source IP setzen (oder Username, je nach Use Case).
  4. Response Limiter setzen, z. B. „1× pro 30 min pro Source IP".
  5. Enable Rule anhaken.
  6. Finish — der Use Case ist live.

5Reference Set für Listen / Whitelists

Optional, aber für sauberes Tuning fast immer nötig — z. B. vertrauenswürdige Scanner/Admin-IPs.

  1. Tab Admin öffnen.
  2. Kachel Reference Set Management anklicken.
  3. Add klicken.
  4. Name, Type (z. B. IP) und Time to Live setzen → Create.
In der Regel testest du dann mit: when any of <property> are contained in any of <reference set>. Befüllen geht manuell, per Import oder automatisch über die Rule-Response „Add to Reference Set".

6Testen & Tunen

  1. Log Activity öffnen, auf das erwartete Event filtern und es künstlich auslösen (z. B. 5 Fehl-Logins).
  2. Unter Offenses prüfen, ob eine neue Offense mit korrektem Index (Source IP) entsteht.
  3. False Positives senken: Whitelists via Reference Set / Building Block, Schwellwert & Zeitfenster anpassen.
  4. Use Case Manager-App → Tuning zeigt rauschende Regeln und Vorschläge.

7MITRE-Mapping (Use Case Manager App)

Die Doku- und Coverage-Ebene des Use Cases — zeigt, welche ATT&CK-Techniken du abdeckst.

  1. App öffnen über Apps → Use Case Manager → Reiter Rules.
  2. Regel suchen und Edit klicken.
  3. Tactic + Technique zuordnen (z. B. Credential Access → T1110 Brute Force).
  4. Save — die MITRE Coverage Map zeigt die Abdeckung danach an.

Checkliste vor „Live"

  • Regeltyp passend (Event / Flow / Common / Offense)
  • Alle blauen Parameter konkretisiert (keine offenen Platzhalter)
  • Whitelist / Ausnahmen über Reference Set oder Building Block
  • Offense-Index sinnvoll (Source IP / Username / …)
  • Response Limiter gesetzt
  • Rule Group + Namenskonvention (z. B. UC-<DOMAIN>-<NR>)
  • Im Test ausgelöst und Offense verifiziert
  • MITRE-Mapping in Use Case Manager hinterlegt
