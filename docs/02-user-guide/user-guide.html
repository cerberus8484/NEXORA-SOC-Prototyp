Nexora SOC

Benutzerhandbuch — User Guide
Version 1.1  |  Gültig ab: 2026-06-20  |  Sprache: Deutsch
Verfügbarkeit: Funktionen mit der Markierung nach Aktivierung liegen im Code vor, sind aber standardmäßig deaktiviert und werden erst durch den Betreiber (Admin/Operator) freigeschaltet. Alle anderen Funktionen sind live.

01 Erste Schritte

Nexora SOC ist eine self-hosted SOC-Orchestrierungsplattform für Analysten der Tier-Stufen 1–3: Incident-Tickets, Threat Hunting, Evidence/Chain-of-Custody, Threat-Intel-Anreicherung und KI-Triage mit menschlicher Freigabe.

Zugriff

Nexora ist erreichbar unter:

https://nexora.example

oder in der lokalen Entwicklung:

http://localhost:5173

Rollen & Berechtigungen

RolleBerechtigung
AdminVollzugriff, Benutzerverwaltung, System-Settings, Provisioning
EngineerHunts, KI-Vorschläge, False-Positive-Regeln, Detections
AnalystTickets, Hunts starten, KI-Vorschläge, Evidence
ViewerLesen von Tickets, Hunts, Detections, NIS2-Readiness
Self-Service für alle: Unabhängig von der Rolle kann jeder Nutzer seine eigene Zwei-Faktor-Authentifizierung und persönliche API-Token im Profil verwalten.

02 Anmeldung

Login

1
Öffne https://nexora.example
2
E-Mail-Adresse eingeben
3
Passwort eingeben
4
Login klicken

Ist die Zwei-Faktor-Authentifizierung für dein Konto aktiv, folgt anschließend die Code-Abfrage — siehe Kapitel 03.

Passwort ändern

Gehe zu Profil (Profilfoto oben rechts), gib das aktuelle und das neue Passwort (mind. 8 Zeichen) ein und bestätige.

Abmeldung

Klick auf dein Profilfoto oben rechts → Abmelden.

Anmeldung mit Passkey (WebAuthn / FIDO2) nach Aktivierung

Hat der Betreiber WebAuthn eingeschaltet und du hast in deinem Profil einen Passkey hinterlegt (z. B. Windows Hello, Touch ID, Sicherheitsschlüssel), erscheint auf der Login-Seite zusätzlich ein Passkey-Button. Ein Klick darauf meldet dich ohne Passwort an — bestätigt über deinen Authenticator.

Hinweis: Passkeys ergänzen die TOTP-Zwei-Faktor- Authentifizierung, sie ersetzen sie nicht. Der Passwort-Login bleibt parallel verfügbar. Einrichtung/Löschung im Profil.

Single Sign-On (SSO / OIDC) nach Aktivierung

Hat der Betreiber eine OpenID-Connect-Anbindung (z. B. an Entra ID / Keycloak) eingerichtet, erscheint auf der Login-Seite ein SSO-Button. Der Passwort-Login bleibt parallel verfügbar. Ob neue Accounts automatisch angelegt oder nur bestehende Konten verknüpft werden, legt der Betreiber fest.

03 Zwei-Faktor-Authentifizierung (MFA/TOTP) live

Nexora unterstützt eine zeitbasierte Zwei-Faktor-Authentifizierung (TOTP), kompatibel mit Google Authenticator, Authy, Microsoft Authenticator u. a. Der zweite Faktor ist ein 6-stelliger Code, der sich alle 30 Sekunden ändert.

MFA ist live, sofern der Betreiber es freigeschaltet hat. Ist es freigeschaltet, entscheidest du als einzelner Nutzer, ob du es einrichtest — es sei denn, der Betreiber hat eine organisationsweite Pflicht aktiviert (siehe unten).

MFA selbst einrichten

1
Gehe zu Profil (Profilfoto oben rechts → Profil)
2
Öffne die Karte Zwei-Faktor-Authentifizierung
3
Klick MFA einrichten
4
Scanne den QR-Code mit deiner Authenticator-App, oder gib das angezeigte Secret (otpauth://) manuell ein
5
Gib den 6-stelligen Code aus deiner App zur Bestätigung ein
6
Klick Aktivieren

Recovery-Codes sichern (einmalig!)

Nach der Aktivierung zeigt Nexora dir eine Liste einmaliger Recovery-Codes.

Wichtig: Diese Codes werden nur ein einziges Mal angezeigt. Speichere sie sicher (Passwort-Manager, ausgedruckt im Tresor). Jeder Code funktioniert genau einmal und erlaubt die Anmeldung, falls du keinen Zugriff auf deine Authenticator-App hast (z. B. Handy verloren). Ohne Authenticator und ohne Recovery-Code muss ein Admin dich entsperren.

Login mit zweitem Faktor

1
E-Mail und Passwort eingeben → Login
2
Bei der Abfrage MFA-Code den aktuellen 6-stelligen Code aus der App eingeben
3
Bestätigen klicken

Alternativ kannst du an dieser Stelle einen deiner Recovery-Codes eingeben (verbraucht den Code).

Organisationsweite MFA-Pflicht

Der Betreiber kann MFA für alle Konten verpflichtend machen (Einstellungen → Sicherheit → MFA-Pflicht). Ist die Pflicht aktiv und du hast noch keine MFA, wirst du direkt beim nächsten Login durch den Einrichtungs-Schritt geführt: QR-Code → Code bestätigen → Recovery-Codes sichern. Erst danach erhältst du Zugang. Bestehende Sitzungen werden nicht ausgesperrt; der Schritt greift beim nächsten Anmelden.

Komponenten

  • Alerts-Heatmap: Alert-Trends der letzten 7 Tage
  • Top Erkennungsquellen: häufigste auslösende Regeln (für Engineer/Admin)

Navigation (Sidebar)

  • Threat Hunts — Hunt-Katalog und laufende Sessions

05 Tickets verwalten

Die Analysis-Seite ist die Hauptwerkbank zur Triage von Incidents.

Ticket-Liste

Filter: State (OPEN/CLOSED) · Status (assigned, in_progress, on_hold, awaiting_customer) · Priority (critical/high/medium/low) · Assigned · Source (wazuh, qradar, splunk, crowdsec, manual). Suche in Titel, Beschreibung und IOCs.

Ticket-Detail

Info-Panel (links): Ticket-Nummer (z. B. INC000001), Titel + Beschreibung, State/Status/Priority, Source, Host, User, Source-/Destination-IP.

Tabs (rechts):

TabInhalt
EvidenceRoh-Event + normalisierte Felder + MITRE-ATT&CK-Taktiken
Threat IntelIOC-Anreicherung (VirusTotal, AbuseIPDB)
HistoryAudit-Trail: wer, wann, was geändert
CommentsAnalyse-Notizen
Relatedverwandte Tickets (gleicher Host / gleiche IP)
ReportIncident- & Kunden-Report als PDF (siehe Kapitel 06)

Ticket bearbeiten

Über Bearbeiten: Status ändern (assigned → in_progress → on_hold), Notizen hinzufügen, dem selbst oder einem anderen Analyst zuweisen.

Ticket schließen

Klick Schließen, wähle einen Schließ-Grund (Gelöst, False Positive, Duplikat, Benign, Sonstiges) und gib optional eine Notiz ein. Geschlossene Tickets können über Reopen wieder geöffnet werden.

Ticket löschen Admin

Nur Admins können Tickets löschen — über den Papierkorb-Button in der Ticket-Liste. Vorher erscheint ein Bestätigungsdialog.

Ticket exportieren

Ticket öffnen → ⋮ → Als PDF exportieren (Titel, Beschreibung, Evidence, History).

06 Reports (Incident- & Kunden-Report)

Aus denselben Ticket-Daten erzeugt Nexora zwei Report-Perspektiven, beide als PDF-Download. Die Buttons liegen im Report-Tab des Tickets.

Incident-Report (technisch)

  • Übersicht (Ticket-Nummer, Schweregrad, Status, Zeitstempel)
  • Analyst-Zusammenfassung
  • Entitäten (Hosts, Benutzer, Prozesse, Netzwerk)
  • Timeline
  • MITRE-ATT&CK-Zuordnung
  • Entscheidung / Empfehlung

Kunden-Report (nicht-technisch)

Für die Weitergabe an Kunden oder das Management — in verständlicher Sprache (Schweregrad und Status in Klartext).

Bewusst ohne technische Details: Der Kunden-Report enthält keine IP-Adressen, keine MITRE-Technik-IDs, keine IOCs und keine Roh-Logdaten. So kannst du ihn ohne weitere Schwärzung an externe Empfänger weitergeben.

Report erzeugen

1
Ticket öffnen
2
In den Tab Report wechseln
3
Incident-Report (PDF) oder Kunden-Report (PDF) klicken
4
Die PDF wird im Browser generiert und heruntergeladen

08 KI-Agent (Copilot)

Der KI-Agent ist dein Analyst-Copilot: Er schlägt Maßnahmen vor — du entscheidest.

Vorschlag anfordern

Ticket öffnen → 🤖 KI-Vorschlag → Typ wählen (False-Positive-Regel, Eskalation, Korrelation, Remediation) → Generieren. Das dauert lokal (Ollama) typisch 10–30 Sekunden.

Vorschlag bewerten

Der Agent zeigt seinen Vorschlag mit einem Confidence-Wert.

  • Akzeptieren — z. B. eine FP-Regel wird übernommen (mit Audit-Eintrag)
  • Ablehnen — Vorschlag verworfen, optional mit Begründung
Human-in-the-Loop: Der Agent schließt nie selbst ein Ticket und führt keine Aktion ohne deine Freigabe aus.

KI-Vorschlag-Queue

Unter KI-Agent verwaltest du alle Vorschläge (Tabs: Ausstehend, Genehmigt, Abgelehnt).

Cloud-Provider (Anthropic/OpenAI/Google) sind opt-in und vom Admin in den Einstellungen wählbar. Bei Cloud-Nutzung verlassen Daten das lokale Netz — bewusste Entscheidung des Betreibers.

09 Detection Library

Die Detection Library zeigt alle Erkennungsregeln.

YARA-Regeln

Über + Neue YARA-Regel legst du Pattern-Matching-Regeln an (Name, Beschreibung, Tags, Patterns, Condition, Severity, Author). Mit YARA Scan testest du einen Text/Befehl gegen die Regeln — passende Regeln werden markiert.

Wazuh-Detections

Read-only-Sicht auf die Wazuh-Erkennungsregeln, suchbar nach Beschreibung, Gruppe und Level. Über Neue Regel können Admins/Engineers eigene Detections anlegen.

10 Evidence & Threat Intelligence

Jedes Ticket wird automatisch angereichert.

IOC-Extraktion

IPs, Domains, Hashes (MD5/SHA-1/SHA-256) und E-Mail-Adressen werden automatisch erkannt.

Automatische TI-Lookups

  • VirusTotal — Hash-/IP-/Domain-Reputation (AV-Engine-Verdicts)
  • AbuseIPDB — IP-Reputation (Abuse-Score 0–100, Kategorien)

Im Tab Threat Intel siehst du eine Tabelle aller IOCs mit Quelle, Score und Verdict (benign / suspicious / malicious). Ein Klick öffnet den vollständigen Report.

Berechtigung: Threat-Intel-Anreicherung ist fuer Analyst, Engineer und Admin gedacht. Viewer koennen vorhandene Ticket- und IOC-Informationen lesen, aber keine neuen externen Provider-Abfragen ausloesen. So werden API-Quota und moegliche IOC-Datenabfluesse begrenzt.

11 Hosts & Inventory

Die Hosts-Seite zeigt die Wazuh-Agenten.

Agent-Status

Tabelle aller registrierten Agenten mit IP, OS, Status (active / disconnected / never_connected) und letztem Heartbeat. Filterbar nach Status und OS-Familie.

Agent-Detail

  • System-Info: Hostname, IP, OS + Version + Architektur, CPU/RAM/Disk
  • Installierte Pakete: Antivirus, Patch-Level, Browser-Versionen
  • Network-Interfaces: aktive NICs, MAC-Adressen, Gateway
  • SCA-Compliance: Sicherheits-Scores, Failed Checks

12 Compliance — NIS2-Readiness

Die Seite Compliance → NIS2 (/compliance/nis2) unterstützt dich, den Stand der NIS2-Risikomanagement-Maßnahmen zu dokumentieren und Nachweise zu sammeln.

Ehrliche Einordnung — bitte beachten: Diese Seite ist eine Arbeits- und Nachweis-Unterstützung. Sie ist kein Konformitätsnachweis, keine Zertifizierung und kein Rechtsgutachten. Nexora behauptet an keiner Stelle, „NIS2-konform" oder „zertifiziert" zu sein. Die Bewertung, ob eine Maßnahme ausreichend ist, triffst du bzw. deine Organisation.

Aufbau

  • KPIs: Anzahl Controls, Evidence-Abdeckung, Review-Bedarf, Überfällige
  • Control-Registry: statischer, versionierter Katalog mit 10 Maßnahmenbereichen (deutsche Titel)
  • Detail-Panel: Status, Nachweise und (für Admins) Bearbeitung je Control

Status setzen Admin

Maßnahme wählen → Status setzen (Nicht begonnen → in Arbeit → adressiert, oder Nicht anwendbar — hierfür ist eine Begründung Pflicht) → speichern. Lesen ab Viewer, Bearbeiten nur Admin.

Nachweise (Evidence) verknüpfen

Je Maßnahme lassen sich Belege hinterlegen (Link auf Richtlinie, Wiki, Dokument); es gibt 8 Evidence-Typen.

Sicherheits-Hinweis zu Links: Erlaubt sind nur http/https-URLs. URLs, die wie Geheimnisse aussehen (Tokens/Passwörter in Query oder Fragment) oder javascript:/data: werden abgelehnt — so gelangen keine versehentlich verlinkten Secrets in die Sammlung.

Incident als Nachweis verknüpfen Admin

Im Control-Detail über „Incident verknüpfen" ein Ticket als Beleg anhängen. Übernommen wird nur ein sicherer Auszug (INC-Nummer, bereinigter Titel, Priorität, State) — keine personenbezogenen Daten (E-Mail, Benutzer, Abteilung, Quell-IP, Notizen, Logs).

Readiness-Signale

  • Überfällig — Frist überschritten
  • Nachweis fehlt — kein Beleg hinterlegt
  • Review nötig — z. B. als adressiert markiert, aber ohne Nachweis
  • Review fällig nach Aktivierung — adressierte Maßnahme mit Nachweis, deren letzter Review älter als die Kadenz ist (Standard 365 Tage)

Management-Report

Im Tab „Management-Report": Status-Verteilung, Evidence-Abdeckung, Incident-Nachweis-Zähler und ein klar gekennzeichneter Disclaimer (kein Konformitätsnachweis). Lesen ab Viewer.

13 Provisioning-Registry nur Admin

Die Seite Provisioning (/provisioning) ist eine Registry zur Verwaltung von Nodes/Agenten (z. B. zusätzlichen Sensoren) — nur für Admins.

Wichtig — was Provisioning NICHT tut: Nexora sendet über diese Funktion keine ausführbaren Befehle an die Nodes, ändert keine Netzwerk-/Firewall-Einstellungen und spielt keine Konfiguration aus. Ein Node meldet sich lediglich (Heartbeat) und erhält als Antwort ausschließlich Status-Informationen — niemals Kommandos.

Enrollment-Profil anlegen

Profil anlegen → Name, Rolle und (read-only) Fähigkeiten des Nodes → speichern.

Enrollment-Token erzeugen (einmalig sichtbar!)

Profil wählen → Token erzeugen. Der Token (enr_…) wird genau einmal in einem Modal angezeigt (mit Kopier-Button).

Wichtig: Der Token erscheint nur dieses eine Mal im Klartext. Sofort kopieren und beim Einrichten des Nodes verwenden. Nexora speichert nur eine Prüfsumme — der Token erscheint danach nirgends mehr (nicht in der Tabelle, nicht im Audit-Log). Geht er verloren, erzeuge einen neuen.

Node-Status & Heartbeat

Je Node siehst du Status (pending, enrolled, active, stale, retired) und letzten Heartbeat (Frische). Das Detail-Modal zeigt IP, OS, Fähigkeiten, Heartbeat-Historie und die Betriebs-Credentials — nur der Präfix, nie das vollständige Credential.

Credential widerrufen / Node stilllegen Admin

  • Credential widerrufen — ein widerrufenes Betriebs-Credential wird sofort ungültig; der Node kann keine Heartbeats mehr senden.
  • Node stilllegen (Retire) — setzt den Node terminal auf retired und widerruft dabei alle aktiven Credentials.

Beide Aktionen fragen über einen Bestätigungsdialog mit Folgenwarnung nach. Viewer/Nicht-Admins sehen den Status, aber keine Schreibaktion.

14 Audit-Log & Export

Das Audit-Log (/audit) protokolliert alle sicherheitsrelevanten Aktionen (append-only, nachträglich nicht änderbar): wer hat was wann an welcher Ressource getan.

Suchen & filtern

Nach Aktion, Akteur, Ressource oder per Freitext.

Export (CSV / PDF)

Oben im Audit-Log das Button-Paar CSV-Export / PDF-Export. Exportiert wird die aktuell gefilterte/durchsuchte Auswahl (Anzahl gedeckelt).

  • CSV-Export — für Excel/Tabellen (UTF-8 mit BOM, gegen Formel-Injektion abgesichert)
  • PDF-Export — paginiertes A4-Quer-Layout mit Kopfzeile und Erstellungs-Zeitstempel

15 Benachrichtigungskanäle nach Aktivierung

Nexora kann Ausgangs-Benachrichtigungen (z. B. zu neuen kritischen Incidents) über mehrere Kanäle versenden. Die Konfiguration der Ziele (URLs, Zugangsdaten) erfolgt durch den Betreiber über Umgebungsvariablen — sie werden nie in der Oberfläche angezeigt.

Standardmäßig ist der Ausgangs-Versand deaktiviert und wird vom Betreiber freigeschaltet.
KanalBeschreibung
SlackNachricht in einen Slack-Channel (Incoming Webhook)
Microsoft TeamsNachricht in einen Teams-Channel
E-Mail (SMTP)E-Mail an eine konfigurierte Adresse
Webhook (generisch)POST an eine beliebige HTTP-Endpunkt-URL

In den Einstellungen zeigt Nexora je Kanal nur an, ob er konfiguriert/aktiv ist („aktiv" / „konfiguriert" / „nicht konfiguriert") — niemals die hinterlegte URL oder Zugangsdaten.

17 Profil & Self-Service

Persönliche Einstellungen verwaltest du auf der Profil-Seite (Profilfoto oben rechts → Profil). Diese Self-Service-Funktionen stehen allen Rollen offen — du musst kein Admin sein, um deine eigene Sicherheit zu verwalten.

Persönliche Daten & Anzeige

  • Anzeigename ändern
  • Passwort ändern (mit altem Passwort, mind. 8 Zeichen)
  • Sprache (Deutsch / Englisch) — dauerhaft gespeichert
  • Datumsformat — dauerhaft gespeichert

Zwei-Faktor-Authentifizierung (MFA)

Die Karte Zwei-Faktor-Authentifizierung erlaubt das Einrichten/Verwalten von MFA. Vollständige Anleitung (QR-Code, Recovery-Codes) in Kapitel 03. Die Karte erscheint, wenn der Betreiber MFA freigeschaltet hat.

Persönliche API-Token (PAT) live

Live, sofern der Betreiber Personal Access Tokens freigeschaltet hat. Mit einem PAT sprichst du die Nexora-API programmatisch unter deinem Konto an (z. B. für Skripte).

Token erstellen: Karte API-Token → Neues Token → Name vergeben → Token wird einmalig angezeigt → sofort kopieren.

Wichtig: Wie alle Secrets wird der Token nur ein einziges Mal angezeigt. Danach ist er nicht mehr einsehbar. Geht er verloren, widerrufe ihn und erstelle einen neuen.

Token widerrufen: Karte API-Token → beim betreffenden Token auf Widerrufen → im Dialog bestätigen. Der Token ist sofort ungültig.

Passkey (WebAuthn) nach Aktivierung

Hat der Betreiber WebAuthn eingeschaltet, findest du eine Karte zum Hinzufügen, Auflisten und Löschen von Passkeys. Damit kannst du dich ohne Passwort anmelden (siehe Kapitel 02).

Bestätigungsdialoge

Sicherheitsrelevante oder unumkehrbare Aktionen (Ticket löschen, Credential widerrufen, Node stilllegen, Passwort zurücksetzen) fragen vorher über einen Bestätigungsdialog nach. Der Dialog beschreibt die Folge; mit Escape oder Abbrechen brichst du ab. Bei länger laufenden Aktionen bleibt der Dialog sichtbar und zeigt einen eventuellen Fehler direkt an.

18 FAQ

Mein Passwort habe ich vergessen. Wie zurücksetzen?

Kontaktiere einen Admin. Der Admin kann in Einstellungen → Benutzerverwaltung dein Passwort zurücksetzen.

Ich habe mein Handy / die Authenticator-App verloren. Wie komme ich rein?

Nutze beim Login statt des 6-stelligen Codes einen deiner Recovery-Codes (jeder Code funktioniert genau einmal). Hast du auch keine mehr, kontaktiere einen Admin — er kann deine MFA zurücksetzen.

Ist Nexora „NIS2-konform" / zertifiziert?

Nein — und das behauptet Nexora bewusst nicht. Die NIS2-Seite ist eine Arbeits- und Nachweis-Unterstützung; sie ist kein Konformitätsnachweis, keine Zertifizierung und kein Rechtsgutachten.

Warum sehe ich die Provisioning-Seite nicht?

Die Provisioning-Registry ist nur für Admins sichtbar und bedienbar.

Verändert Provisioning meine Nodes / mein Netzwerk?

Nein. Es werden keine ausführbaren Befehle gesendet und keine Netzwerk-/Firewall- Einstellungen geändert. Nodes melden sich nur (Heartbeat) und erhalten ausschließlich Status-Informationen zurück.

Wo richte ich MFA oder ein API-Token für mich selbst ein?

Auf der Profil-Seite — das geht für alle Rollen, nicht nur für Admins (siehe Kapitel 17).

Wie exportiere ich einen Report?

Schnell-Export: Ticket öffnen → ⋮ → Als PDF exportieren. Oder im Tab Report: Incident-Report (PDF) (technisch) bzw. Kunden-Report (PDF) (nicht-technisch, ohne IPs/MITRE/IOCs).

Kann ich Tickets löschen?

Nur Admins. Geschlossene Tickets bleiben aus Audit-Gründen erhalten — stattdessen schließen mit passendem Grund.

Gibt es einen Dark Mode?

Ja — über das Theme-Toggle (Mond-Icon) oben rechts im Header.

Kann der KI-Agent Tickets automatisch schließen?

Nein. Der Agent macht nur Vorschläge, die du genehmigst oder ablehnst.
