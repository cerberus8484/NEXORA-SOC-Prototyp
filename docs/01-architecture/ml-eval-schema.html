Schema v1

ML-Eval-Schema

Kleines, redigierbares, providerunabhaengiges JSONL-Format fuer den ersten Offline-Eval von Nexora.

01 Ziel

Ein gemeinsames Austauschformat fuer redigierte Offline-Eval-Snapshots, zuerst fuer agent_suggestion und ticket.

02 Format

  • Dateiformat: jsonl
  • Encoding: UTF-8
  • Eine Zeile = ein JSON-Objekt = ein evalbarer Fall
  • Backend-Export: POST /api/v1/ml/eval/export
  • Rolle: admin; Formate: jsonl oder json; Limit: 1..1000
  • Quellen: reviewed AgentSuggestion und geschlossene Ticket-Outcomes
  • Offline-Report: cd backend && npm run ml:eval-report -- ../docs/01-architecture/ml-eval-sample.jsonl
  • Gold-Sample-Profil: label_source="gold_review" mit Outcome-Label, outcome-faehigem Raw-Verdict, reviewed_at und redigiertem human_reason

03 Pflichtfelder

FeldBedeutung
schema_versionStart mit v1
entity_typeagent_suggestion oder ticket
entity_idID der bewerteten Entitaet
ticket_idTicket-Referenz
label_sourceQuelle des menschlichen Labels
created_atZeit des Ursprungssignals
reviewed_atZeit des Reviews oder null
human_labelnormalisierter Zielwert

04 Kernfelder

Wichtige Zusatzfelder fuer den ersten Eval: kind, source_system, source_model, raw_verdict, raw_confidence, review_status, human_reason, close_reason, priority.

05 Human Labels

  • accepted
  • rejected
  • false_positive
  • benign
  • suspicious
  • incident
  • resolved_other
accepted/rejected sind Review-Labels, die anderen eher Outcome-Labels. Diese Ebenen sollen spaeter getrennt ausgewertet werden.

06 Normalisierung

  • Confidence immer auf 0..1
  • Zeit immer als ISO-8601 UTC
  • Freitext nur kurz und redigiert

07 Mapping

AgentSuggestion: approved -> accepted, rejected -> rejected, Confidence direkt aus 0..1.

Ticket: closeReason=false_positive -> false_positive, sonst Mapping ueber decision; Ticket-Confidence wird von 0..100 auf 0..1 geteilt.

08 Beispiel

Ein konkretes Beispiel liegt in docs/01-architecture/ml-eval-sample.jsonl.

Ein kuratiertes Gold-Sample-Beispiel liegt in docs/01-architecture/ml-gold-sample.jsonl.

Der erste Backend-Exporter und ein Offline-Slice-Report sind umgesetzt. Fuer vergleichbare Outcome-Labels berechnet der Report ein vorsichtiges Agreement; Review-Labels werden dabei uebersprungen. Der Threshold-Sweep zeigt Coverage, akzeptierte Predictions und Review-Routing fuer die Schwellen 0, 0.5, 0.7 und 0.9. Das Routing-Gate ist fail-closed und verlangt standardmaessig Agreement 0.8, Coverage 0.5 und mindestens 20 Gold-Records. Naechste Schritte sind echte Snapshots, kuratierte Gold-Samples und daraus belastbare Routing-Gates.
