HUNT-009

AD Enumeration

MITRE: T1087.002 · T1069.002 · T1018 · T1558.003 · T1003.006  |  Taktik: Discovery  |  Basis-Konfidenz: 50

Beschreibung

Erkennt Active Directory Enumeration durch Angreifer die nach privilegierten Accounts, Gruppen, ACLs und Angriffspfaden suchen. BloodHound/SharpHound stellen sehr charakteristische LDAP-Abfragen. PowerView-Funktionen wie Get-DomainUser haben erkennbare Commandline-Patterns. net.exe-Abfragen mit /domain-Flag von Workstations sind verdächtig.

Ziel: Angreifer vor DCSync, Kerberoasting oder Lateral Movement erkennen. AD Enumeration ist fast immer ein Vorläufer einer tieferen Kompromittierung — wer das Environment kartiert, plant den nächsten Schritt.

QRadar AQL

LDAP-Abfragen von Nicht-Admin-Workstations (BloodHound-Pattern)

-- LDAP-Abfragen von Nicht-Admin-Workstations (BloodHound-Pattern)
SELECT sourceip, username, destinationip,
       COUNT(*) AS ldap_query_count,
       UNIQUECOUNT(LDAPFilter) AS unique_filters
FROM events
WHERE category = 'LDAP'
  AND sourceip NOT IN (SELECT ip FROM reference_set:'Domain Controllers')
  AND sourceip NOT IN (SELECT ip FROM reference_set:'Admin Workstations')
  AND (LDAPFilter ILIKE '%(samAccountType=805306368)%'
    OR LDAPFilter ILIKE '%(objectCategory=groupPolicyContainer)%'
    OR LDAPFilter ILIKE '%(ms-ds-machineaccountquota=*)%'
    OR LDAPFilter ILIKE '%(userAccountControl:1.2.840.113556.1.4.803:=4194304)%')
GROUP BY sourceip, username, destinationip
HAVING ldap_query_count > 50
LAST 1 HOURS

-- net.exe Domain-Abfragen von Workstations
SELECT sourceip, username, ProcessName, CommandLine
FROM events
WHERE EventID = 4688
  AND ProcessName ILIKE '%net%'
  AND (CommandLine ILIKE '%user /domain%'
    OR CommandLine ILIKE '%group "Domain Admins"%'
    OR CommandLine ILIKE '%group "Enterprise Admins"%'
    OR CommandLine ILIKE '%localgroup administrators%')
  AND sourceip NOT IN (SELECT ip FROM reference_set:'Admin Workstations')
LAST 24 HOURS

-- nltest / dsquery / Active Directory Module
SELECT sourceip, username, ProcessName, CommandLine
FROM events
WHERE EventID = 4688
  AND (
    (ProcessName ILIKE '%nltest%' AND CommandLine ILIKE '%dclist%')
    OR (ProcessName ILIKE '%dsquery%' AND CommandLine ILIKE '%-limit 0%')
    OR CommandLine ILIKE '%Get-ADUser -Filter *%'
    OR CommandLine ILIKE '%Get-ADGroupMember%'
  )
LAST 24 HOURS

Splunk SPL

-- BloodHound/SharpHound LDAP-Abfragen erkennen
index=wineventlog EventCode=4662
| where match(Properties,"(?i)(samAccountType|objectCategory|ms-ds-machineaccountquota)")
  AND NOT match(SubjectUserName,"\\$")
| stats count as query_count, values(Properties) as queried_attrs
  by SubjectUserName, SubjectDomainName, src_ip, _time span=5m
| where query_count > 20
| eval bloodhound_score=case(
    query_count > 200, 90,
    query_count > 100, 75,
    query_count > 50,  60,
    1==1, 40)

-- PowerView-Patterns in PowerShell
index=sysmon EventCode=1 Image="*\\powershell.exe"
| where match(CommandLine,
    "(?i)(Get-DomainUser|Get-DomainGroup|Get-DomainTrust|Get-DomainController|Invoke-Kerberoast|Find-LocalAdminAccess|Get-NetLocalGroupMember|Get-DomainComputer)")
| table _time, ComputerName, User, CommandLine

-- Massenhafter Kerberos TGT Request (AS-REQ Recon)
index=wineventlog EventCode=4768
| stats count as ticket_count by src_ip, TargetUserName, _time span=10m
| where ticket_count > 30
| eval comment="Möglicher AS-REP Roasting Recon oder BloodHound"

Sysmon / Windows Security Events

-- Typische BloodHound/SharpHound LDAP-Filter:
--   (samAccountType=805306368)   → alle User-Accounts
--   (samAccountType=268435456)   → alle Gruppen
--   (objectCategory=computer)   → alle Computer
--   (ms-ds-machineaccountquota=*) → Machine Account Quota
--   (userAccountControl:...:=4194304) → DONT_REQUIRE_PREAUTH (AS-REP Roasting)

-- Sysmon Event 1: Prozess-Erstellung
-- SharpHound.exe direkt: Prozessname "SharpHound" erkennbar
-- Umbenannt: Commandline enthält "--CollectionMethod All" oder "--ZipFilename"

-- WinSec Event 4662: Objekt-Zugriff
-- Sehr viele 4662 Events in kurzer Zeit = LDAP Enumeration
-- Besonders verdächtig wenn: SubjectUserName kein Service-Account

-- net.exe Patterns:
--   net user /domain              → alle Domain-User
--   net group "Domain Admins" /domain
--   net accounts /domain          → Passwort-Policy (Kerberoasting-Info)

-- nltest Patterns:
--   nltest /dclist:domain.local   → alle DCs auflisten
--   nltest /dsgetsite             → Site-Informationen

True Positives

  • SharpHound.exe direkt ausgeführt von Workstation (Konfidenz: 98) — Prozessname oder Commandline enthält SharpHound, --CollectionMethod All oder --ZipFilename von Nicht-Admin-Workstation
  • >200 LDAP-Queries mit BloodHound-Filtern in 5 Min (Konfidenz: 90) — Massenhafter Abruf von samAccountType, objectCategory und verwandten Filtern von einer einzigen Workstation
  • PowerView Get-DomainUser + Get-DomainGroup in einer PS-Session (Konfidenz: 88) — Mehrere PowerView-Funktionen sequenziell in einer PowerShell-Session deuten auf systematische Enumeration hin
  • net user /domain + net group "Domain Admins" von Standard-User (Konfidenz: 75) — net.exe-Abfragen mit /domain-Flag von einer Workstation ohne Admin-Whitelist
  • nltest /dclist von Workstation (Konfidenz: 70) — DC-Auflistung durch einen Standard-User ist kein legitimes Szenario

False Positives & Whitelist

  • Legitime AD-Management durch Domain-Admins — Whitelist: Admin-Workstations + Admin-Accounts, die täglich AD verwalten
  • Monitoring Tools (SCOM, Nagios) — Diese Systeme fragen AD regelmäßig ab. Whitelist: Monitoring-Server IPs und bekannte Service-Accounts
  • HR-Software mit LDAP-Integration — Bekannte Business-Applikationen mit festen, wiederkehrenden LDAP-Filtern. Whitelist: Applikations-Server + Filtermuster
  • Identity Management Tools (AD Connect, etc.) — Whitelist: bekannte Service-Accounts dieser Tools, die im Normalfall sehr hohe LDAP-Aktivität erzeugen

Varianten & Evasion-Techniken

  • VAR-001: ldapdomaindump Python (Conf-Modifier: -10) — Python-Tool, kein .NET, anderes User-Agent-Pattern in LDAP-Verbindung. Kein SharpHound-Prozess sichtbar
  • VAR-002: ADRecon PowerShell (Conf-Modifier: -5) — Sehr ähnliche Patterns wie BloodHound, aber andere LDAP-Filter-Reihenfolge. PowerShell Commandline erkennbar
  • VAR-003: CrackMapExec --users (Conf-Modifier: 0) — SMB-basierte Enumeration statt LDAP. Andere Event-IDs (4624, 4776), kein LDAP-Traffic
  • VAR-004: Stufenweise Enumeration (niedrig und langsam) (Conf-Modifier: -30) — Queries über Stunden verteilt um Schwellwerte zu unterschreiten. Erfordert Baseline-Analyse statt einfacher Zählung
