HUNT-001

C2 / Beaconing Detection

MITRE: T1071.001, T1095, T1571, T1090  |  Taktik: Command and Control  |  Quellen: Firewall, Proxy, Sysmon 3+22, DNS

2. Beschreibung

Dieser Hunt erkennt periodisches Beaconing-Verhalten, das typisch fur Command-and-Control-Implantate ist. Angegriffene Systeme verbinden sich in regelmasigen Intervallen mit einem externen Server — oft mit minimalem Jitter (Cobalt Strike Default: 60s, 0% Jitter) oder einem berechneten Pseudo-Random-Intervall (Malleable C2 mit Jitter-Faktor).

Das Kernprinzip: Legitimer Nutzerverkehr zeigt hohe Varianz in Verbindungsintervallen. C2-Beaconing zeigt niedrige Standardabweichung (STDDEV) der Intervalle uber einen langeren Zeitraum. Kombiniert mit kleinen, gleichformigen Paketgroßen und suspekten User-Agents ergibt sich ein starkes Signal.

Warum es funktioniert: Menschen surfen nicht in 60-Sekunden-Zyklen. Maschinen schon. Die Standardabweichung der Verbindungsintervalle ist das starkste Signal — bei echtem C2 liegt sie typischerweise unter 15 Sekunden.
Limitation: Hochfrequenz-Beaconing (<5s) produziert extrem viele Events. Sleep Obfuscation (variierendes Sleep mit Jitter bis 50%) erhoht die STDDEV und kann diesen Hunt umgehen.

3. QRadar AQL

Beacon Pattern Query — Interval STDDEV

-- HUNT-001: C2 Beaconing Detection via QRadar AQL
-- Erkennt periodische Verbindungsmuster zu externen IPs
-- Quellen: Firewall Netflow, Sysmon Event 3

SELECT
    sourceip                                          AS src_ip,
    destinationip                                     AS dst_ip,
    destinationport                                   AS dst_port,
    COUNT(*)                                          AS connection_count,

    -- Zeitliche Intervall-Analyse
    MAX(starttime) - MIN(starttime)                   AS observation_window_sec,
    (MAX(starttime) - MIN(starttime)) / COUNT(*)      AS avg_interval_sec,

    -- Standardabweichung der Intervalle (approximiert via Varianz)
    SQRT(
        AVG(POWER(starttime - (
            SELECT AVG(starttime)
            FROM events e2
            WHERE e2.sourceip = events.sourceip
              AND e2.destinationip = events.destinationip
        ), 2))
    )                                                 AS interval_stddev,

    -- Datenmenge je Verbindung (gleichformige Beacons haben aehnliche Bytezahl)
    AVG(eventpayload)                                 AS avg_bytes,
    STDDEV(eventpayload)                              AS bytes_stddev,

    -- Zeitraum
    MIN(DATEFORMAT(starttime, 'yyyy-MM-dd HH:mm:ss')) AS first_seen,
    MAX(DATEFORMAT(starttime, 'yyyy-MM-dd HH:mm:ss')) AS last_seen

FROM events

WHERE
    -- Nur ausgehende Verbindungen zu externen IPs
    INCIDR('10.0.0.0/8', destinationip) = FALSE
    AND INCIDR('172.16.0.0/12', destinationip) = FALSE
    AND INCIDR('192.168.240.0/16', destinationip) = FALSE
    AND INCIDR('127.0.0.0/8', destinationip) = FALSE

    -- Relevante Event-Kategorien: Firewall Permit + Sysmon Net
    AND (
        category = 'Firewall Permit'
        OR (qid = 5000012 AND EventID = '3')  -- Sysmon Event 3
    )

    -- Zeitfenster: letzte 24 Stunden
    AND starttime > (NOW() - 86400000)

    -- Nur TCP/UDP (kein ICMP auf diesem Hunt)
    AND protocol IN (6, 17)

GROUP BY
    sourceip,
    destinationip,
    destinationport

HAVING
    -- Mindestens 10 Verbindungen im Beobachtungszeitraum
    connection_count >= 10

    -- Durchschnittliches Intervall zwischen 30s und 600s (typischer C2-Bereich)
    AND avg_interval_sec BETWEEN 30 AND 600

    -- Niedrige Standardabweichung = hochregulares Timing
    AND interval_stddev < 15

    -- Mindestbeobachtungszeitraum: 10 Minuten
    AND observation_window_sec > 600

ORDER BY
    interval_stddev ASC,   -- Niedrigste STDDEV zuerst = regularstes Beaconing
    connection_count DESC

LIMIT 200;

DNS Beacon Query (lange NXDomain-Ketten)

-- HUNT-001b: DNS-basiertes C2 Beaconing
-- Quelle: DNS Resolver Logs (Sysmon Event 22)

SELECT
    sourceip                     AS client_ip,
    domainname                   AS queried_domain,
    COUNT(*)                     AS query_count,
    COUNT(DISTINCT domainname)   AS unique_subdomains,

    -- Entropie-Indikator: lange Subdomains = Base64/Hex encoded
    AVG(LENGTH(domainname))      AS avg_domain_length,
    MAX(LENGTH(domainname))      AS max_domain_length,

    -- Record-Typ-Verteilung (TXT/NULL = Tunnel-Indikator)
    SUM(CASE WHEN recordtype = 'TXT'  THEN 1 ELSE 0 END) AS txt_count,
    SUM(CASE WHEN recordtype = 'NULL' THEN 1 ELSE 0 END) AS null_count,
    SUM(CASE WHEN recordtype = 'A'    THEN 1 ELSE 0 END) AS a_count,

    MIN(DATEFORMAT(starttime, 'yyyy-MM-dd HH:mm:ss')) AS first_seen,
    MAX(DATEFORMAT(starttime, 'yyyy-MM-dd HH:mm:ss')) AS last_seen

FROM events

WHERE
    -- DNS Events
    (EventID = '22' OR category = 'DNS Query')
    AND starttime > (NOW() - 86400000)

    -- Externe Domains (eigene Domains ausschliessen)
    AND domainname NOT LIKE '%.intern'
    AND domainname NOT LIKE '%.local'
    AND domainname NOT LIKE '%.corp'

GROUP BY
    sourceip,
    -- Basisdomaene extrahieren (letzte 2 Labels)
    SUBSTRING(domainname, LENGTH(domainname) - POSITION('.' IN REVERSE(domainname)) - POSITION('.' IN SUBSTRING(REVERSE(domainname), POSITION('.' IN REVERSE(domainname))+1)) + 2)

HAVING
    -- Viele Queries zur gleichen Basisdomain
    query_count >= 50

    -- Oder lange Subdomains (Encoding-Indikator)
    OR avg_domain_length > 30

    -- Oder TXT/NULL Records (Tunnel-Indikator)
    OR (txt_count + null_count) > 5

ORDER BY
    (txt_count + null_count) DESC,
    avg_domain_length DESC,
    query_count DESC

LIMIT 100;

4. Splunk SPL

Beacon Score — Zeitbasierte Erkennung

`*** HUNT-001: C2 Beaconing Detection — Splunk SPL ***`
`*** Index: firewall, sysmon | Zeitraum: -24h ***`

index=firewall OR index=sysmon
    (EventCode=3 OR sourcetype="pan:traffic" OR sourcetype="cisco:asa")
    action=allowed OR action=permitted
    earliest=-24h

`-- Nur externe Ziel-IPs --`
| where NOT match(dest_ip, "^10\.")
    AND NOT match(dest_ip, "^172\.(1[6-9]|2[0-9]|3[0-1])\.")
    AND NOT match(dest_ip, "^192\.168\.")
    AND NOT match(dest_ip, "^127\.")

`-- Zeitstempel als Unix-Sekunden normalisieren --`
| eval epoch = if(isnum(_time), _time, strptime(_time, "%Y-%m-%dT%H:%M:%S"))

`-- Pro Connection Group: Intervalle berechnen --`
| sort 0 src_ip dest_ip dest_port epoch
| streamstats window=2 current=true
    last(epoch) AS prev_epoch
    by src_ip dest_ip dest_port
| eval interval_sec = epoch - prev_epoch
| where interval_sec > 0 AND interval_sec < 7200

`-- Aggregation pro Host-Ziel-Paar --`
| stats
    count                    AS conn_count,
    avg(interval_sec)        AS avg_interval,
    stdev(interval_sec)      AS stdev_interval,
    min(epoch)               AS first_seen_epoch,
    max(epoch)               AS last_seen_epoch,
    avg(bytes_out)           AS avg_bytes,
    stdev(bytes_out)         AS stdev_bytes,
    values(dest_port)        AS ports_used
    by src_ip dest_ip

`-- Zeitfenster-Berechnung --`
| eval observation_min = round((last_seen_epoch - first_seen_epoch) / 60, 1)
| eval first_seen = strftime(first_seen_epoch, "%Y-%m-%d %H:%M:%S")
| eval last_seen  = strftime(last_seen_epoch,  "%Y-%m-%d %H:%M:%S")

`-- Beacon Score berechnen (0-100) --`
| eval beacon_score = 0

`  Regulares Timing: niedrige STDDEV = hoher Score`
| eval beacon_score = beacon_score + case(
    stdev_interval < 5,   40,
    stdev_interval < 15,  30,
    stdev_interval < 30,  15,
    stdev_interval < 60,   5,
    true(),                0
)

`  Ausreichend Verbindungen`
| eval beacon_score = beacon_score + case(
    conn_count >= 100, 20,
    conn_count >= 50,  15,
    conn_count >= 20,  10,
    conn_count >= 10,   5,
    true(),             0
)

`  Typische C2-Intervalle (30-300s)`
| eval beacon_score = beacon_score + case(
    avg_interval >= 30  AND avg_interval <= 65,  20,
    avg_interval >= 65  AND avg_interval <= 300, 15,
    avg_interval >= 300 AND avg_interval <= 600, 10,
    true(),                                        0
)

`  Gleichformige Paketgrosse`
| eval beacon_score = beacon_score + case(
    stdev_bytes < 50,  10,
    stdev_bytes < 200,  5,
    true(),             0
)

`  Schwellwert: nur Score >= 40 weiterverarbeiten`
| where beacon_score >= 40

`-- Zusaetzliche Anreicherung --`
| eval risk_level = case(
    beacon_score >= 80, "CRITICAL",
    beacon_score >= 60, "HIGH",
    beacon_score >= 40, "MEDIUM",
    true(),             "LOW"
)

`-- Ausgabe --`
| table
    risk_level beacon_score
    src_ip dest_ip ports_used
    conn_count avg_interval stdev_interval
    avg_bytes observation_min
    first_seen last_seen

| sort - beacon_score

5. Sysmon / Windows Events

Sysmon Event 3 — Netzwerkverbindungen verdaechtige Prozesse

-- Sysmon Event ID 3: NetworkConnect
-- Erkennt ungewoehnliche Prozesse mit ausgehenden Verbindungen

index=sysmon EventCode=3 earliest=-24h

`-- Prozesse die keine Netzwerkverbindungen haben sollten --`
| where match(Image, "(?i)(notepad|calc|mspaint|wordpad|explorer|svchost)\.exe$")
    OR (match(Image, "(?i)powershell\.exe$") AND Initiated="true")
    OR (match(Image, "(?i)(cmd|wscript|cscript|mshta)\.exe$") AND Initiated="true")

`-- Externe Ziele --`
| where NOT match(DestinationIp, "^(10\.|172\.(1[6-9]|2[0-9]|3[01])\.|192\.168\.|127\.)")

| stats
    count AS conn_count,
    values(DestinationIp)   AS dest_ips,
    values(DestinationPort) AS dest_ports,
    dc(DestinationIp)       AS unique_dests
    by Computer Image User SourcePort

| where conn_count >= 3

| sort - conn_count

Sysmon Event 22 — DNS Queries auf verdaechtige Domains

-- Sysmon Event ID 22: DNSEvent
-- Erkennt ungewoehnliche DNS-Anfragen (hohe Entropie, TXT-Records)

index=sysmon EventCode=22 earliest=-24h

`-- Subdomains mit hoher Entropie (Laenge > 20 Zeichen vor erstem Punkt) --`
| rex field=QueryName "^(?P<subdomain>[^.]+)\."
| eval subdomain_len = len(subdomain)
| where subdomain_len > 20

`-- ODER: bekannte C2/Tunnel-Indikatoren --`
| where match(QueryName, "(?i)\.(xyz|top|club|pw|tk|ga|cf|ml)$")
    OR match(QueryName, "[0-9a-f]{32,}")     -- Hex-Strings
    OR match(QueryName, "[A-Za-z0-9+/]{20,}") -- Base64-Strings

| stats
    count AS query_count,
    values(QueryName)    AS queried_domains,
    avg(subdomain_len)   AS avg_subdomain_len,
    dc(QueryName)        AS unique_domains
    by Computer User Image

| sort - query_count

6. True Positives

  1. TP-001Cobalt Strike Default Profile
    Verbindungsintervall exakt 60 Sekunden, STDDEV < 2s. User-Agent: Mozilla/5.0 (compatible; MSIE 9.0; Windows NT 6.1; Trident/5.0) (CS-Default). Self-signed TLS-Zertifikat auf Port 443. Prozess: beacon.exe, svchost.exe oder injizierter Prozess. EventID 3 (Sysmon) mit konstanter Bytezahl.
    85
  2. TP-002Cobalt Strike Malleable C2 (angepasstes Profil)
    Beaconing mit konfiguriertem Jitter (z.B. 20%). STDDEV zwischen 5-12s bei 60s Basis-Intervall. Legitim aussehende URI-Pfade (/jquery-3.3.1.slim.min.js). Header-Profile imitieren bekannte Software. Erkennung via Jitter-Analyse und Paketgroessen-Fingerprinting.
    65
  3. TP-003Meterpreter HTTPS Reverse Shell
    Port 443 oder 4444. Verbindungsintervall 5-30s (Standard). Prozess typischerweise injiziert in explorer.exe, notepad.exe oder svchost.exe. TLS-Zertifikat: selbstsigniert, CN oft generisch. Gleichfoermige Paketgroessen durch Stage-Traffic.
    75
  4. TP-004DNS C2 (DNScat2 / iodine)
    TXT oder NULL Record Queries. Subdomains: Base64-kodierte Daten, Laenge 30-60 Zeichen. Query-Frequenz: 10-100/min zur gleichen Basisdomain. Sysmon Event 22: QueryName mit hex/base64-Pattern. EventID 22, QueryResults: TXT-Antworten mit Nutzdaten.
    80
  5. TP-005HTTP Beacon mit Jitter (generische Implantate)
    Interval 30-300s mit 10-30% Jitter. POST-Requests an statische URI. Kleine Payloads (100-500 Bytes). User-Agent konsistent (kein Browser-Update). Evtl. HTTP 200 mit verschluesseltem Body (erkennbar an hoher Entropie der Antwort).
    55

7. False Positives

  1. FP-001Windows Update / WSUS
    Regelmaessige Check-in-Verbindungen zu windowsupdate.microsoft.com und WSUS-Server alle 60-90 Minuten. Whitelist: *.microsoft.com, *.windowsupdate.com, lokaler WSUS-Server-IP-Bereich.
  2. FP-002CrowdStrike / AV-Agenten
    EDR-Agenten beacon zum Management-Server mit konfigurierten Intervallen (Standard: 30-60s). Whitelist: bekannte EDR-Management-IPs, Prozesse wie CSFalconService.exe, MsMpEng.exe.
  3. FP-003Monitoring-Agenten (Nagios/Zabbix/PRTG)
    Zabbix-Agent: alle 60s Check-in zur Zabbix-Server-IP. Nagios NRPE: auf Anfrage. Whitelist: Monitoring-Server-IPs, Ports 10050 (Zabbix), 5666 (NRPE), 161 (SNMP).
  4. FP-004Backup-Software (Veeam/Backup Exec)
    Backup-Agenten verbinden sich periodisch zum Backup-Server. Whitelist: Backup-Server-IPs, bekannte Backup-Agenten-Prozesse.
  5. FP-005NTP (Network Time Protocol)
    UDP Port 123, alle 64-1024 Sekunden. Sehr kleine Pakete (48 Bytes). Einfach herauszufiltern: UDP/123 von Port 123.
  6. FP-006Browser-Telemetrie / Auto-Update
    Chrome, Firefox, Edge: regelmaessige Updates und Telemetrie. Whitelist: *.google.com, *.mozilla.org, *.microsoft.com fur bekannte Browser-Prozesse.

8. Varianten & Evasion

VAR-001 Domain Fronting

C2-Traffic wird uber legitime CDN-Domains (Cloudflare, Azure, Akamai) geleitet. Der SNI-Header zeigt eine legitime Domain, der Host-Header zeigt die echte C2-Domain. Konfidenz-Modifier: -15.
Erkennung trotzdem: TLS-Inspektion (SNI vs. tatsaechlicher Server-IP), ungewoehnliche Zieldomains mit Cloud-IPs aber hohem Traffic-Volumen, Proxy-Logs zeigen unterschiedliche CONNECT-Ziele.

VAR-002 Sleep Obfuscation

Beacon-Payload ist im Speicher verschluesselt waehrend er schlaeft. Jitter-Faktor bis 50% macht Timing-Analyse schwieriger. STDDEV steigt auf 15-30s. Konfidenz-Modifier: -20.
Erkennung trotzdem: Prozess-Memory-Analyse (encrypted heap sections), langerer Beobachtungszeitraum (24h statt 1h), Volatility-Analyse fur CS-Beacons.

VAR-003 SMB P2P Beacon (CS-Feature)

Interne Hosts kommunizieren uber Named Pipes (\\.\pipe\*). Nur ein Host hat externe C2-Verbindung. Lateral Movement via SMB-Beacon. Konfidenz-Modifier: +10 wenn kombiniert mit Sysmon Event 17/18 (PipeEvent).
Erkennung: Sysmon Event 17 PipeName enthalt CS-Default-Namen (postex_ssh_*, mojo.*), ungewoehnliche SMB-Verbindungen zwischen Workstations.

VAR-004 IPv6 C2

C2-Traffic uber IPv6 — viele Firewalls/SIEMs ignorieren IPv6 standardmaessig. Konfidenz-Modifier: -10 wenn IPv6-Monitoring fehlt.
Erkennung: Explizit IPv6-Netflow-Logs einsammeln, Sysmon Event 3 erfasst auch IPv6-Verbindungen. AAAA-Record-Anfragen fur C2-Domains.

VAR-005 ICMP Tunneling

C2-Daten werden in ICMP Echo Request/Reply Paketen versteckt. Erkennung durch diesen Hunt (TCP/UDP fokussiert) erschwert. Konfidenz-Modifier: -25.
Erkennung: ICMP-Pakete mit ungewoehnlicher Payloadgroesse (> 64 Bytes), hohe ICMP-Rate zu einer einzelnen externen IP, ICMP-Payload-Entropie-Analyse.

9. Konfidenz-Berechnung

# HUNT-001 Confidence Scoring — Python Pseudocode
# Basis: 40 Punkte (Beaconing-Pattern erkannt)

def calculate_confidence(beacon: BeaconEvent) -> int:
    score = 40  # Basis: Beaconing-Pattern mit STDDEV < 15s detektiert

    # --- Timing-Praezision ---
    if beacon.interval_stddev < 2:
        score += 25   # Sehr primaer: CS-Default (kein Jitter)
    elif beacon.interval_stddev < 8:
        score += 15   # Geringer Jitter
    elif beacon.interval_stddev < 15:
        score += 5    # Moderater Jitter

    # --- Bekannte C2-Intervalle ---
    if beacon.avg_interval == 60:
        score += 10   # CS-Default-Intervall
    elif 30 <= beacon.avg_interval <= 120:
        score += 5

    # --- Verbindungsanzahl ---
    if beacon.conn_count >= 100:
        score += 10
    elif beacon.conn_count >= 50:
        score += 5

    # --- Paketgroessen-Uniformitaet ---
    if beacon.bytes_stddev < 50:
        score += 10
    elif beacon.bytes_stddev < 200:
        score += 5

    # --- Verdaechtiger Prozess ---
    suspicious_procs = ['notepad.exe', 'calc.exe', 'explorer.exe',
                        'svchost.exe', 'werfault.exe']
    if beacon.process_name in suspicious_procs:
        score += 15

    # --- Evasion-Abzuege ---
    if beacon.uses_domain_fronting:
        score -= 15
    if beacon.jitter_factor > 0.3:
        score -= 20
    if beacon.uses_ipv6:
        score -= 10

    # --- Cap ---
    return min(100, max(0, score))

# Schwellwerte fuer Aktionen:
# >= 90: Sofort eskalieren, Isolation vorschlagen
# 70-89: An Analyst eskalieren, Evidence sammeln
# 50-69: Ticket erstellen, weitere Analyse
# 30-49: Nur loggen
# < 30:  Verwerfen
